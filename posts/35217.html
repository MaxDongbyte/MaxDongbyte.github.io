用 Cloudflare 部署 Cloud Mail：成本、限制与适用场景

发表于2026-07-08|解锁小魔盒
|总字数:1.2k|阅读时长:3分钟|浏览量:

1. 背景与原理

更新说明（2026-07-16）：本文所说的“免费”仅指在 Cloudflare 当前免费额度内可能不产生账单，不代表无限容量、永久免费或零维护成本。正式使用前请核对项目许可证、Cloudflare 最新定价以及邮件服务条款。

传统邮箱系统（如 Gmail、Outlook）虽然稳定，但存在以下限制：

  • 免费版空间有限
  • 自定义域名邮箱需要付费
  • 邮件存储受限
  • 隐私依赖第三方平台

Cloud-Mail 是一个开源项目，利用 Cloudflare Workers + Pages + KV + D1 + Resend 等免费资源，实现：

  • 自建邮箱系统
  • 自定义域名邮箱
  • 可按项目设计使用 KV、D1 或 R2 存储，但容量和请求数受套餐额度限制
  • 零成本部署
  • 可以自行管理应用配置与部分邮件数据，但底层基础设施仍由云服务商提供

原理非常简单：

Cloudflare Workers 负责邮件路由与 API，KV/D1/R2 负责存储，Resend 负责邮件发送。

你只需要一个 Cloudflare 账号 + GitHub 账号，就能搭建属于自己的邮箱系统。

2. 适用场景

以下用户最适合使用 Cloud‑Mail：

✔ 想拥有自定义域名邮箱

如：

  • admin@yourdomain.com
  • contact@yourdomain.com

✔ 想学习自定义域名收信与邮件路由

不受 Gmail / Outlook 限制。

✔ 想自建隐私邮箱

邮件不经过第三方平台。

✔ 想零成本搭建邮箱系统

Cloudflare 免费额度足够个人使用。

✔ 想学习 Cloudflare Workers / Pages

Cloud‑Mail 是非常好的入门项目。

3. 风险与限制

❗ 1. Cloudflare 免费额度有限

Workers、KV、D1 都有免费限制，极端高频使用可能触发限流或者产生费用。

❗ 2. Resend 免费额度有限

邮件发送量过大可能需要付费。

❗ 3. 邮件系统需要维护

如：

  • API 变更
  • Workers 更新
  • Resend 签名验证

❗ 4. 不适合企业级大规模邮件

Cloud‑Mail 更适合个人或小团队。

❗ 5. 邮件送达率依赖 Resend

如果域名配置不当，可能进入垃圾邮件。

❗ 6. 自建邮箱系统需要一定技术基础

需要理解 Cloudflare、GitHub、API、KV、D1 等概念。

4. 完整步骤

以下步骤适配 2026 年最新 Cloud‑Mail 部署流程。

4.1 注册 Cloudflare 与 GitHub

  • 注册 Cloudflare：https://cloudflare.com
  • 注册 GitHub：https://github.com

4.2 克隆 Cloud‑Mail 项目到自己的仓库

登录 GitHub → 打开项目：

https://github.com/maillab/cloud-mail

点击 Fork 克隆到自己的仓库。

4.3 在 Cloudflare 中部署 Workers

✔ 创建 Worker

✔ 导入 GitHub 项目

⚠️ 注意：部署路径不要改变

✔ 添加变量与密钥

✔ 添加并绑定 KV 与 D1 数据库

✔ 初始化项目数据库

浏览器输入：https://你的worker域/api/init/你的jwt_secret

将：

  • 你的worker域 替换为你的自定义域名
  • 你的jwt_secret 替换为你设置的密钥

4.4 设置收件路由规则

Cloudflare Email Routing → 添加规则 → 指向 Worker。

4.5 邮件发送设置（Resend）

✔ 注册 Resend

https://resend.com

✔ 添加 Domain 与 API Key

复制 API Key。

✔ 添加 Webhook（发送状态回调）

Webhook 地址：https://你的worker域/api/webhooks

选择 email events（至少勾选 9 项）。

5. 常见错误与解决方案

❌ 错误 1：Worker 无法访问 KV / D1 / R2

解决： 检查绑定是否正确。

❌ 错误 2：初始化失败

解决：

  • 检查 jwt_secret 是否一致
  • 检查 Worker 域名是否正确

❌ 错误 3：邮件无法发送

解决：

  • 检查 Resend API Key
  • 检查域名 DNS 记录
  • 检查 webhook 是否配置正确

❌ 错误 4：邮件无法接收

解决：

  • 检查 Email Routing
  • 检查 Worker 路由规则
  • 检查 KV 是否正常写入

6. 我的真实使用体验

以下是我的真实体验总结：

✔ Cloud‑Mail 部署非常简单

只需要 Cloudflare + GitHub，无需服务器。

✔ 邮件接收稳定

KV + D1 存储可靠。

✔ 邮件发送依赖 Resend

送达率高，但需要正确配置域名。

✔ 小规模测试可能落在免费额度内

适合个人长期使用。

✔ 自定义域名邮箱非常爽

如：

  • hello@yourdomain.com
  • admin@yourdomain.com

✔ 适合学习 Cloudflare 技术栈

Workers、Pages、KV、D1 都能实际体验。

7. 总结与建议

✔ Cloud‑Mail 更适合作为可审计的学习或轻量收信方案

无需服务器、无需付费。

✔ 适合个人与小团队

不适合企业级大规模邮件。

✔ 配置正确后非常稳定

尤其是收件功能。

✔ 建议长期使用 Resend

送达率高、配置简单。

✔ 本教程仅提供技术参考

请确保你的行为符合相关法律法规与平台政策。
